# Scripts CI really runs, but not under a name any workflow spells out, and
# scripts that are deliberately hand-run. One path per line, then the reason.
# check-workflows (wired, LibreSCRS/ci) treats every line here as a reachability root, so what
# these scripts call counts as run too. A path that stops being tracked fails.
packaging/ci/build-deb.sh  run as packaging/ci/build-$FAMILY.sh by packaging/ci/package-gate.sh:142
packaging/ci/build-rpm.sh  run as packaging/ci/build-$FAMILY.sh by packaging/ci/package-gate.sh:142
ci/scripts/changelog-to-debian.sh  hand-run when refreshing packaging/debian/changelog; no CI step consumes it
tools/sr_cyrillic_to_latin.py  hand-run after every lupdate pass to regenerate the Latin-script catalogue from the Cyrillic one (CONTRIBUTING.md); no CI step consumes it, the i18n audit only spells its path inside a remediation hint
scripts/pre-commit-clang-format.sh  A git hook a developer installs locally, so nothing in CI names it by design; the same rule is enforced on every push by the format job.
scripts/pre-commit-i18n.sh  An opt-in local hook that runs the i18n audit incrementally against the working tree; CI runs the same audit over the whole tree, so the hook has no CI caller.
scripts/prepare-signing-bundle.sh  Assembles a signing bundle with a custom JRE and a prebuilt startup archive; it needs the signing toolchain and is run when a release bundle is cut, not on a push.
scripts/macos/icons/createIcons.sh  Regenerates the icon assets that are committed next to it; it runs when the artwork changes and its output, not the script, is what the build consumes.
