# Format:   <workflow>:<job>[:<step-number>]<two or more spaces><reason>
#
# workflow-step-order.py requires a row for every gate step whose job or step
# condition cannot be shown to hold on push. Same discipline as
# gate-wiring-exceptions.txt: an empty reason fails, a row naming a job that no
# longer exists fails, and a row that excuses something needing no excuse fails.
# The last one is what makes these rows disappear when the condition does.

ci.yml:license-drift-guard    The packaging half of this job runs only when the change touched packaging, decided by a path filter in an earlier job. This row goes if that filter goes.
ci.yml:coverage    The coverage job runs only on workflow_dispatch: the ratchet compares against a baseline recorded in one environment, and the runner image moves the compiler under it. This row goes when the job moves to push on a pinned environment.
ci.yml:package    No repository or organisation variable named PACKAGE_JOB_ENABLED exists, so this job has never run once and the packaging gate it carries has never judged anything. This row goes when the release decision on distribution packages for the agent is taken, either way.
